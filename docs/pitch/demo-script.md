# Демо-скрипт «КӨЗ» — пошагово (3 минуты)

> Один спикер, один ноутбук. Все экраны на русском. URL демо: **http://127.0.0.1:8000/**
> Команда запуска сервера: **`run.bat`** (поднимает venv + uvicorn на 127.0.0.1:8000;
> ставит `KOZ_AUTO_DISCOVER=1` и `KOZ_DEEP_DISCOVER=1` — фон сам ищет реальные посты и
> делает глубокий разбор топ-кандидата).

## Подготовка (до выхода на сцену, НЕ в зачёт времени)
1. Закрыть старые процессы uvicorn (иначе держат лок на `data/koz.db`):
   `powershell -Command "Get-Process -Name python -ErrorAction SilentlyContinue | Stop-Process -Force"`.
2. Предзащитный smoke-тест: `python -m scripts.dry_run` — печатает таблицу `[OK ] ... -> 200`
   по всем эндпоинтам и финальную `DRY-RUN OK` (exit 0). Плюс `python -m pytest tests -q` → all green.
3. Поднять приложение: **`run.bat`**. Дать ему **~2 минуты** до выхода: фон успевает найти
   реальные посты (YouTube + Telegram) И глубоко разобрать топ-1 — в ленте появляется
   красный пост с уже заполненным блоком «Доказательства» (без ручной 90-сек проверки на сцене).
4. Открыть `http://127.0.0.1:8000/` — лента отсортирована по риску (красные сверху), вверху
   панель «Автономный поиск опасного контента». В шапке — macro-F1 нашей модели (~0.95).
5. Вторая вкладка про запас: `http://127.0.0.1:8000/api/metrics` (macro-F1, F1 по классам,
   confusion matrix — критерий №2).
6. Если есть сеть — заранее проверить, что кнопка «Найти опасное» отрабатывает (Блок 1).
   Если сети нет — демо целиком на уже найденных/кэшированных постах (см. лестницу фоллбэков).

## Прогон (3:00)

### Блок 1 (0:00–0:40) — Проблема + АВТОНОМНЫЙ поиск (наш «крючок»)
- Кадр: главный экран `/`, лента реальных постов, отсортированная по риску
  (красный ≥70 / жёлтый 40–69 / зелёный <40). Карточки — с **реальными превью и кликабельными
  ссылками** на оригинал (YouTube `watch?v=…`, Telegram `t.me/…`); бейдж источника
  («YouTube-поиск» / «Telegram»).
- Действие: нажать **«Найти опасное в интернете»** → фоновая задача (прогресс-бар) обходит
  соцсети по скам-запросам RU/KZ через yt-dlp `ytsearch` и публичные Telegram-каналы, скорит
  находки нашей моделью и кладёт реальные посты в ленту. Показать «Найдено N · флагнуто M».
- (Опц.) показать сегментный фильтр площадки (Все/YouTube/Telegram/TikTok/Instagram) и
  тумблер **«глубокий разбор видео»** (аудио→текст, текст с экрана, визуальные маркеры).
- Сказать: масштаб (тысячи роликов/день) → система **сама находит** реальные опасные посты с
  точными ссылками, а не работает по подсунутому списку.

### Блок 2 (0:40–1:55) — Drill-down + ДОКАЗАТЕЛЬСТВА + метрики + PDF (ЯДРО, критерий №2)
- Действие: кликнуть верхний красный пост → карточка `GET /api/post/{id}`. Сверху играет
  скачанный клип (или превью + «Открыть оригинал»).
- Показать блок **«Доказательства · разбор по модальностям»**:
  - **Речь → текст** (Whisper) — транскрипт, с подсветкой триггер-слов (промокод, бренд);
  - **Текст с экрана (OCR)** — распознанная «табличка на видео» (промокоды/бонусы поверх кадра);
  - **Визуальные маркеры** (open-CLIP) — напр. `betting_slip 97%`.
- Показать **«Сработавшие паттерны модели»** (наши сигналы с весами) и блок **«Почему опасно»**
  (объяснение на русском) + рекомендованное действие (эскалация / на проверку / авто-очистка).
- Сказать ключевое: модель **наша**, обучена локально (TF-IDF слова + char_wb + наши
  инженерные сигналы → sklearn LogisticRegression), **с казахстанскими сигналами**
  (Kaspi/Halyk-переводы, суммы в тенге, +7 7XX, локальные бренды 1хбет/мелбет/Финико,
  казахскоязычная лексика). Whisper/OCR/CLIP — локальные **фичеризаторы**, не сервис решения;
  LLM в скоринге нет.
- Действие: «Экспорт дела (PDF)» → `GET /api/report/{id}.pdf`, открыть PDF (досье с
  доказательствами). Переключиться на вкладку `GET /api/metrics`: macro-F1 ~0.95, F1 по классам,
  confusion matrix (недиагональная — честная).

### Блок 3 (1:55–2:20) — Граф связей
- Действие: вкладка **«Граф»** (перерисовывается при входе; тянет `GET /api/graph`).
- Показать: кластер — несколько post-узлов, связанных общими entity-узлами (один бренд казино /
  один Telegram-канал / один промокод/реквизит) → координированная сеть.
- Сказать: руками такие скрытые связи не вылавливаются — ценность графа.

### Блок 4 (2:20–2:45) — Мониторинг + Живая проверка
- Действие: вкладка **«Мониторинг»** — каналы под наблюдением со статистикой
  (последний скан / собрано / флагнуто), фон сканирует их периодически. Это «непрерывный»
  контур, а не разовый прогон.
- (Опц., если есть сеть и время) вкладка **«Живая проверка»**: вставить ссылку →
  `POST /api/analyze` (async, прогресс) → реальный мультимодальный разбор за ~минуту.
  Если сети нет — пропустить, доказательства уже видны в Блоке 2 на найденном посте.

### Блок 5 (2:45–3:00) — Тренды + этика + масштаб
- Действие: вкладка **«Тренды»** (`GET /api/trends`) — динамика по категориям/платформам,
  гистограмма риска, топ брендов.
- Сказать: human-in-the-loop (приоритизация, НЕ блокировка), объяснимость, аудит-лог,
  только публичные данные; путь MVP (SQLite) → прод (Postgres + очередь + объектное хранилище).

## Лестница фоллбэков (что отрезаем при проблемах, сверху вниз)
| Условие | Действие на сцене |
|---|---|
| Нет сети / «Найти опасное» не идёт | Не жать кнопку. Лента уже наполнена ранее найденными реальными постами (в БД) + seed-кэш — скоринг мгновенный, всё локально. Демо целиком на уже имеющихся постах. |
| Фоновый deep не успел / видео не качается | Drill-down всё равно показывает наш скоринг, паттерны и объяснение по тексту заголовка; блок доказательств даёт корректный empty-state. Усилить рассказ о модели + метриках. |
| Тяжёлые модели (Whisper/CLIP/OCR) не встали | Не запускать live-upload и deep. Текстовый путь (лента + drill-down + паттерны + PDF + метрики) от них не зависит. |
| Граф тормозит/пуст | Пропустить Блок 3, усилить Блок 2 (drill-down + доказательства + PDF + метрики — ядро критерия №2). |
| `/api/metrics` отдаёт 404 | Модель не обучена — `python -m app.model.train` до выхода; в крайнем случае рассказать схему модели по слайду. |
| Совсем нет сервера / падение | Заранее снятые скриншоты консоли + готовый PDF-досье + `koz-pitch.md`. Рассказать по слайдам. |
| Кончается время | Минимальный зачётный путь: Блок 1 (лента + автопоиск) → Блок 2 (drill-down + доказательства + метрики + PDF). Это закрывает критерии №2 и №5. |

## Гарантированный офлайн-режим (cache-only)
- Демо НЕ требует сети для ядра: seed-посты и их признаки закэшированы в `data/demo_posts.jsonl`,
  грузятся в БД при старте (lifespan), скоринг мгновенный; ранее найденные реальные посты тоже
  лежат в `data/koz.db`.
- Любой эндпоинт ядра (`/api/feed`, `/api/post/{id}`, `/api/report/{id}.pdf`, `/api/metrics`,
  `/api/graph`, `/api/trends`, `/api/watchlist/stats`) отвечает локально без сети.
- Сетевые пути — «Найти опасное» (`POST /api/discover`), «Живая проверка» (`POST /api/analyze`),
  фоновый поиск/deep — все опциональны и деградируют мягко (сбои проглатываются, без 500).

> Примечание: кнопки «Тик» больше нет — лента обновляется автоматически (поллинг) и кнопкой
> «Обновить»; реальные посты приходят из автопоиска и фонового мониторинга.
