# Демо-скрипт «КӨЗ» — пошагово (3 минуты)

> Один спикер, один ноутбук. Все экраны на русском. URL демо: **http://127.0.0.1:8000/**
> Команда запуска сервера: **`run.bat`** (поднимает venv + uvicorn на 127.0.0.1:8000).

## Подготовка (до выхода на сцену, НЕ в зачёт времени)
1. Закрыть старые процессы uvicorn (иначе они держат лок на `data/koz.db`):
   `powershell -Command "Get-Process -Name python -ErrorAction SilentlyContinue | Stop-Process -Force"` (или закрыть прошлый терминал).
2. Запустить предзащитный smoke-тест: `python scripts/dry_run.py` — должно напечатать таблицу
   `[OK ] ... -> 200` по всем эндпоинтам и финальную строку `DRY-RUN OK` (exit code 0).
3. Поднять приложение: `run.bat` (поднимает venv + uvicorn на http://127.0.0.1:8000).
4. Открыть в браузере `http://127.0.0.1:8000/` — видна лента с уже раскрытыми постами,
   отсортированная по риску (красные сверху).
5. Подготовить во второй вкладке `http://127.0.0.1:8000/api/metrics` (метрики собственной модели:
   macro-F1, F1 по классам, confusion matrix).
6. Если есть сеть — заранее открыть/скопировать тестовую ссылку для live-разбора (см. Блок 4).
   Если сети нет или сомневаемся — заранее решаем: Блок 4 пропускаем (он всегда опционален).

## Прогон (3:00)

### Блок 1 (0:00–0:30) — Проблема + лента
- Кадр: главный экран `/`, лента отсортирована по риску (красный ≥70 / жёлтый 40–69 / зелёный <40).
- Действие: нажать кнопку «Тик» (вызывает `POST /api/tick`) 1–2 раза — новые посты «капают» в
  ленту и авто-скорятся нашей моделью, очередь пересортировывается.
- Сказать: масштаб проблемы (тысячи роликов/день) → почему нужен AI → приоритетная очередь.

### Блок 2 (0:30–1:45) — Drill-down + доказательства + метрики + PDF (ЯДРО, критерий №2)
- Действие: кликнуть верхний (красный) пост → открывается карточка `GET /api/post/{id}`.
- Показать: транскрипт речи (Whisper), OCR-текст с экрана, визуальные концепты (CLIP),
  список сработавших паттернов (top_features с весами), блок «Почему опасно» (объяснение на
  русском), рекомендованное действие (escalate / review / auto_clear).
- Действие: нажать «Экспорт дела (PDF)» → скачивается `GET /api/report/{id}.pdf`. Открыть PDF.
- Переключиться на вкладку метрик `GET /api/metrics`: показать macro-F1, F1 по классам и
  confusion matrix.
- Сказать: «модель наша, обучена нами локально (TF-IDF + наши сигналы + sklearn-голова),
  без внешних API в скоринге; Whisper/OCR/CLIP — это локальные фичеризаторы, не сервисы решения».

### Блок 3 (1:45–2:15) — Граф связей
- Действие: открыть экран графа (тянет `GET /api/graph?min_risk=70`).
- Показать: кластер — несколько post-узлов, связанных общими entity-узлами
  (один бренд казино / один Telegram-канал / один промокод) → координированная сеть.
- Сказать: руками такие скрытые связи не вылавливаются — это и есть ценность графа.

### Блок 4 (2:15–2:45) — Live-разбор (ОПЦИОНАЛЬНО, только если есть сеть)
- Действие: на экране «Live-проверка» вставить ссылку → `POST /api/analyze` с JSON `{url}`.
  ИЛИ загрузить видео-файл (multipart `file`) → тот же `POST /api/analyze`.
- Показать: реальный мультимодальный разбор → пост + extracted + score (вердикт за секунды).
- ЕСЛИ нет сети / тяжёлые модели не отвечают → ПРОПУСТИТЬ, сразу к Блоку 5 (см. лестницу ниже).

### Блок 5 (2:45–3:00) — Тренды + этика + масштаб
- Действие: открыть экран трендов (`GET /api/trends`) — динамика по категориям/платформам,
  распределение по рекомендованным действиям, гистограмма риска, топ брендов.
- Сказать: human-in-the-loop (приоритизация, не блокировка), объяснимость, аудит-лог,
  путь MVP (SQLite) → прод (Postgres + очередь + объектное хранилище).

## Лестница фоллбэков (что отрезаем при проблемах, сверху вниз)
| Условие | Действие на сцене |
|---|---|
| Нет сети / live-fetch не идёт | Пропустить Блок 4 (`POST /api/analyze` с URL). Демо целиком на кэше — все seed-посты уже имеют пред-вычисленные признаки (`data/demo_posts.jsonl`), скоринг мгновенный. |
| Тяжёлые модели (Whisper/CLIP/OCR) не встали | Не запускать live-upload вообще. Кэш-датасет (Блоки 1–3,5) не зависит от тяжёлых моделей — extracted закэширован. |
| Граф тормозит/пуст | Пропустить Блок 3, усилить Блок 2 (drill-down + PDF + метрики — это ядро критерия №2). |
| `/api/metrics` отдаёт 404 | Модель не обучена — запустить тренировку (`setup.bat` / `python -m app.model.train`) до выхода; в крайнем случае рассказать схему модели по слайду 3. |
| Совсем нет сервера / падение | Открыть заранее снятые скриншоты консоли + готовый PDF-досье + `koz-pitch.md`. Рассказать по слайдам. |
| Кончается время | Минимальный зачётный путь: Блок 1 (лента) → Блок 2 (drill-down + метрики + PDF). Это закрывает критерии №2 и №5. |

## Гарантированный офлайн-режим (cache-only)
- Демо НЕ требует сети: seed-посты и их признаки закэшированы в `data/demo_posts.jsonl`,
  загружаются в БД при старте (lifespan), скоринг мгновенный.
- Тяжёлые модели предзагружаются на этапе `setup.bat`; в cache-only они не нужны вообще.
- Любой эндпоинт из Блоков 1–3,5 (`/api/tick`, `/api/feed`, `/api/post/{id}`, `/api/report/{id}.pdf`,
  `/api/metrics`, `/api/graph`, `/api/trends`) отвечает локально без сети.
- Единственный сетевой путь — Блок 4 (`POST /api/analyze` по URL); он всегда опционален.
