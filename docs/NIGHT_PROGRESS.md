# Ночной прогресс улучшения модели КӨЗ

> Автономный цикл `/loop`: улучшаем детектинг **финпирамид / мошенников / криптосхем**
> + определение TG-чатов + режим прямых эфиров. Только модель. Букмекеров не трогаем.

## Как одним запросом вернуть состояние проекта

```bash
python -m scripts.eval_holdout      # точность на фиксированном реалистичном наборе
python -m pytest tests -q           # все тесты зелёные
git log --oneline -15               # что сделано за ночь
```
Либо просто прочитать этот файл — он обновляется каждую итерацию.

## Методология (почему замер честный)

Synthetic `macro_f1` раздувается из-за запоминания шаблонных фраз (TF-IDF, min_df=1)
→ его рост ничего не доказывает. Поэтому создан **фиксированный held-out набор**
`data/eval_holdout.jsonl` (реалистичные примеры, которые модель НЕ видит на обучении)
+ скрипт `scripts/eval_holdout.py`. Улучшение = рост точности на ЭТОМ наборе, при
`macro_f1` в норме [0.80–0.99] и зелёных тестах.

## Сводка метрик (held-out набор, расширяется по ходу: сейчас 94 примера, RU + KZ)

| метрика | базовая | текущая |
|---|---|---|
| **threat-recall** (доля угроз, не отнесённых к clean) | 70% | **98%** |
| overall accuracy | 75% | **95%** |
| fraud (мошенничество/крипто/pump-and-dump, RU+KZ) | 50% | **97%** |
| pyramid (HYIP/MLM/взаимопомощь, RU+KZ) | 85% | **88%** |
| clean-specificity (нет ложных тревог) | 93% | **100%** |
| macro_f1 (synthetic, в норме [0.8–0.99]) | 0.934 | 0.902 |

Осталось 4 промаха из 88: 3 крипто-HYIP помечены `fraud` вместо `pyramid` (защитимо,
угроза поймана) + 1 соц.инженерия «переведи другу» без платёжных ключей.

## Журнал итераций

### Итерация 1 — расширенный детектинг мошенничества (fraud 50% → 94%)
- **Проблема:** held-out показал fraud = 50% — модель не ловила фишинг/имперсонацию
  (банк/налоговая/Нацбанк), фейковые призы/гранты, job/предоплата-скам и крипто-схемы
  (арбитраж/бот/майнинг/удвоение). Ядровые FRAUD-шаблоны были только про крипто-даблер.
- **Сделано:**
  - 3 новых handcrafted-сигнала в `features.py`: `scam_payment_demand` (требование
    оплаты/перевода/реквизитов), `fake_prize_grant` (фейк-выигрыш/приз/грант),
    `crypto_scam` (удвоение/арбитраж/майнинг/раздача); расширен `payout_promise`
    (ловит «гарантированный заработок/прибыль», не только «доход»). Русские подписи
    в `explain.py`.
  - Новые реалистичные FRAUD-шаблоны в `gen_dataset.py` (фишинг/призы/job/крипто) +
    clean-хард-негативы (те же схемы в предупреждениях) + boundary-коллизии
    fraud↔clean (держат macro_f1 в норме).
- **Результат:** threat-recall 70%→91%, fraud 50%→94%, overall 75%→88%,
  macro_f1 0.925, **555 тестов зелёные**, dry_run OK. Закоммичено.

### Итерация 2 — детектинг финпирамид (HYIP/MLM-вербовка): pyramid 61% → 89%
- **Расширил held-out** до 60 примеров (бинарные матрицы, пожизненные выплаты,
  стейкинг, remote-access fraud) — чтобы не переобучаться на фиксированном наборе.
  На расширенном наборе pyramid просел до 61% (модель не ловила вербовку в структуру).
- **Сделано:**
  - Новый сигнал `pyramid_recruit` в `features.py`: бинарные матрицы, пожизненные
    выплаты, реинвест-удвоение, команда основателей, уровни структуры, оборот сети,
    «места тают», «вложил-снял». Расширен `scam_payment_demand` (remote-access:
    «переведите на безопасный/резервный счёт», «установите приложение по ссылке»).
  - PYRAMID-вербовочные шаблоны + clean-предупреждения (те же маркеры в памятках) +
    boundary pyramid↔clean + remote-access fraud-шаблоны в `gen_dataset.py`.
- **Результат:** pyramid 61%→89%, overall 83%→95%, threat-recall 85%→**98%**,
  **clean-specificity 95%→100% (ноль ложных тревог)**, macro_f1 0.924. 555 тестов
  зелёные, dry_run OK. Закоммичено.

### Итерация 3 — определение TG-чатов (`scan.py`)
- **Починен баг:** в регулярке `_TME_LINK_RE` альтернатива `joinchat/<hash>` затенялась
  общим username-паттерном → приватный инвайт `t.me/joinchat/<hash>` ошибочно ловился
  как канал «joinchat», а не как чат-лид. Поставил `joinchat/` первым — инвайты чатов
  теперь распознаются корректно.
- **Расширил `_CHAT_HINT`** индикаторами чатов RU/KZ/EN + транслит: беседка/общалка/
  форум/флудилка/курилка/комьюнити/sohbet/пікірталас (раньше только chat/group/обсужд/чат).
- **Тест** `test_links_from_text_classifies_chats_channels_and_invites` фиксирует
  классификацию: инвайты + чат-username → чаты-лиды, обычные каналы → channels,
  служебные t.me-пути отсеяны.
- **Результат:** 556 тестов зелёные, dry_run OK. Закоммичено. (Классификатор не
  трогался — это слой discovery/ingestion.)

### Итерация 4 — режим прямых эфиров: динамический поиск живых Twitch-эфиров
- **Проблема:** для Kick уже был динамический поиск живых эфиров (`search_kick_live`),
  а Twitch проверял только фиксированных сид-стримеров через `fetch_live` — если они
  офлайн, находок 0.
- **Сделано:** `search_twitch_live` в `streaming.py` — публичный Twitch GraphQL
  (web Client-ID, без авторизации) отдаёт каналы, которые СЕЙЧАС в эфире в гемблинг-
  категориях (Slots / Virtual Casino). Подключён в `discover` live-петлю рядом с Kick
  (best-effort, через `streaming_mod`-seam, фильтр полосы опасности применяется).
- **Проверено вживую:** нашёл 6 живых казино-стримов Twitch (hunterowner «$120,000
  WAGER», volcanicdogg «1WIN», flushflushd976 «400K Giveaway» и др.).
- **Результат:** 559 тестов зелёные (+3 новых: парсинг GQL, устойчивость, ингест),
  dry_run OK. Теперь и Kick, и Twitch live-discovery находят эфиры динамически, даже
  когда сид-аккаунты офлайн. Закоммичено.

### Итерация 5 — KZ-язычный детектинг fraud/pyramid: KZ-fraud 84% → 96%
- **Расширил held-out** до 72 примеров, добавив казахскоязычные fraud/pyramid/clean.
  Модель отлично держала KZ-clean (100% specificity, ноль ложных), но **пропускала
  KZ-fraud/pyramid** — новые сигналы (scam_payment_demand/fake_prize_grant/
  pyramid_recruit) были только на русском.
- **Сделано:**
  - Расширил 3 сигнала казахскими паттернами: «ақысын төле / смс кодын айтыңыз /
    картаңыз бұғатталды» (scam_payment_demand), «ұтып алдыңыз / жүлдені алу»
    (fake_prize_grant), «өмір бойы төлем / матрицада орын / қатысушы тарт / желі
    кеңей» (pyramid_recruit).
  - KZ-шаблоны в `gen_dataset.py`: фишинг/призы/налог + lifetime/матрица-вербовка +
    KZ-clean-предупреждения + KZ boundary-коллизии.
- **Результат:** KZ-fraud 84%→96%, pyramid 86%→91%, overall (72) 90%→96%,
  threat-recall обратно **98%**, specificity **100%**, macro_f1 0.915. 559 тестов
  зелёные, dry_run OK. Закоммичено.

### Итерация 6 — устойчивость к обфускации (регрессия-гард)
- **Проверил** детектинг на обфусцированных угрозах (приём мошенников): разрядка
  «к а з и н о», гомоглифы «1хбет»/«дoхoд», leetspeak «к4з1н0», soft-hyphen,
  zero-width, точки между буквами — RU + KZ. Результат: **11/11 пойманы** (risk
  59–100, все не-clean). Слой `normalize_obfuscated` уже снимает обфускацию.
- **Сделано:** добавлен регрессионный тест `tests/model/test_obfuscation_robustness.py`
  — фиксирует, что обфусцированные угрозы остаются не-clean. Защищает ночные
  переобучения модели от потери де-обфускации (улучшать сам слой не потребовалось).
- **Результат:** 560 тестов зелёные, dry_run OK. Закоммичено.

### Итерация 7 — расширение эталона (72→88) + новые схемы (pump-and-dump, касса взаимопомощи)
- **Расширил held-out** до 88: pump-and-dump, NFT/seed-фишинг, фейк-инвест-советник,
  касса взаимопомощи, gifting-пирамида, MLM + ЛЕГАЛЬНЫЕ хард-негативы (лицензированная
  биржа, благотворительность, MLM-работа, крипто-памятки) — честная проверка обобщения.
- **Пробелы:** модель не ловила pump-and-dump («монета взлетит x50, инсайд»),
  фейк-советника, кассу взаимопомощи, gifting-пирамиду (84% pyramid / 88% fraud).
- **Сделано:** расширил `crypto_scam` (pump-and-dump: «монета взлетит x\d / инсайд /
  закупайтесь / подключи кошелёк / seed-фраза») и `pyramid_recruit` («касса
  взаимопомощи / круг замкнётся / дарим друг другу»). Шаблоны pump-and-dump /
  советник / касса-дарение + ЛЕГАЛЬНЫЕ крипто/MLM/благотворительность хард-негативы +
  усиленные «регулятор предупреждает: X — пирамида» памятки (RU+KZ), чтобы вернуть
  specificity к 100%.
- **Результат:** fraud 88→**97%**, pyramid 84→**88%**, overall 91→**95%**,
  threat-recall 92→**98%**, **specificity обратно 100%** (0 ложных даже на легальной
  бирже/благотворительности/MLM), macro_f1 0.902. 560 тестов зелёные, dry_run OK.

### Итерация 8 — соц.инженерия: эталон 88→94 + регрессия-гард в действии
- **Расширил held-out** до 94: соц.инженерия «выручи деньгами / переведи родственнику,
  верну позже, не звони» (скам) + легальные переводы близким/долги/советы (хард-негативы).
- **Вывод:** модель УЖЕ хорошо ловит соц.инженерию (ясные случаи «сынок/брат/мама,
  срочно переведи» → fraud) и держит легальные переводы как clean (specificity 100%).
  Это обобщение из iter2 (FRAUD_REMOTE) — отдельное обучение не требовалось.
- **Регрессия-гард сработал:** попытка добавить ещё соц.инженерия-шаблоны подняла
  пограничный «перевод другу» (36→49), но `test_obfuscation_robustness` поймал, что
  это размыло детектинг zero-width «казино» (стало clean r51) → **изменение откатано**.
  Модель осталась в состоянии iter7 (obfuscation 11/11). Методология «измеряй и не
  допускай регрессий» сработала как задумано.
- **Результат:** eval 94 примера, overall 96%, threat-recall 98%, specificity 100%.
  Один устойчивый пограничный промах («перевод другу, верну завтра» — почти неотличим
  от реальной просьбы; форсировать опасно для specificity). 560 тестов зелёные.
