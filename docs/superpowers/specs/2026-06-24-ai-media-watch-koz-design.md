**Трек:** AI Media Watch — выявление признаков незаконного игорного бизнеса и финансовых пирамид в социальных сетях
**Команда:** стек = Claude Code (инженер — Claude Code, команда направляет и защищает)

## 0. Контекст задачи (из положения)

Требуется AI-решение, которое **на постоянной основе автоматически собирает и анализирует видеоконтент** из соцсетей (Instagram, TikTok и др.) для выявления признаков незаконного игорного бизнеса, финпирамид и мошеннических схем. Система должна:
- анализировать **видео, аудиодорожку, текст, субтитры и визуальные маркеры**;
- распознавать паттерны: реклама нелицензированных онлайн-казино, обещания гарантированного дохода, агрессивные инвестпризывы, реферальные схемы, скрытые способы вовлечения;
- автоматически **формировать риск-оценку**, **объяснять выявленные признаки** и **приоритизировать** материалы для дальнейшей проверки.

### Критерии оценки (каждый 20 баллов, всего 100) → как закрываем
1. **Актуальность + обоснование AI** — реальная проблема РК; AI обоснован (масштаб соцсетей не разобрать вручную).
2. **Наличие AI-модели, независимой от иных сервисов** — собственный обученный риск-классификатор; скоринг полностью локальный, без внешних платных API. Показываем метрики.
3. **ИБ + этика** — только публичные данные, минимизация PII, human-in-the-loop, объяснимость, контроль ложных срабатываний, аудит-лог.
4. **Практическая реализуемость + масштабируемость** — модульная архитектура, путь MVP→прод, оценка пропускной способности.
5. **Качество презентации + тех-защита MVP** — отполированная аналитическая консоль, живой сквозной демо-сценарий за 3 минуты.

**Приз направления:** 2 000 000 ₸ (I — 1 000 000 / II — 700 000 / III — 300 000). ≥60% призовых — на развитие проекта.

## 1. Продукт и пользователь

**Рабочее название:** «КӨЗ» (KÓZ) — каз. «глаз/взгляд». ИИ-«глаз» АФМ над соцсетями.
**Подзаголовок:** *AI Media Watch — мониторинг соцсетей на признаки незаконного гемблинга и финпирамид.*

**Пользователь:** аналитик АФМ (Департамент экономических расследований).

**Ценность одной фразой:** система непрерывно «втягивает» посты из соцсетей, авто-оценивает риск, выстраивает **приоритетную очередь** «что проверять первым» и по клику показывает **доказательства по каждой модальности + объяснение + рекомендованное действие**.

Это 1-в-1 повторяет формулировку трека: *собирать → анализировать (видео/аудио/субтитры/текст/визуал) → риск-оценка → объяснение → приоритизация для проверки.*

## 2. Архитектура

```
[Ingestion]              [Multimodal Extractors]      [OUR MODEL]            [Decision]           [UI: Аналит. консоль]
seed-feed (симуляция  →  audio → Whisper              fusion risk-           risk 0–100        →  лента (live-поток)
   непрерыв. потока)     frames → OCR (EasyOCR)        классификатор      →  + категория          очередь по риску
yt-dlp (live link)       frames → CLIP (zero-shot)     (обучаем САМИ)         + объяснение         drill-down (доказательства)
upload видео (live)      caption/субтитры → текст      multiling embeddings   + рекоменд. действие live-upload
                              ↓ признаки кэшируются         + наши признаки         ↓                граф связей / тренды / PDF
                                      SQLite (посты · признаки · сущности · скоры · аудит-лог)
```

**Принцип:** каждый блок изолирован, имеет чёткий интерфейс и тестируется отдельно. Внешних платных API в скоринге нет — всё локально (критерий №2).

### Компоненты и их границы
- **Ingestion** — отдаёт «посты» (метаданные + ссылка на медиа). Источники: seed-датасет (симуляция непрерывного потока), live-ссылка (yt-dlp), live-загрузка файла. *Вход:* источник. *Выход:* запись поста в очередь.
- **Extractors** — из медиа достают признаки по модальностям. *Вход:* пост+медиа. *Выход:* `{caption, transcript, ocr_text, visual_concepts[], entities[]}`. Кэшируются.
- **OUR MODEL** — наш обученный классификатор. *Вход:* фьюзнутые признаки. *Выход:* `{risk: 0..100, category, class_probs, top_features[]}`.
- **Decision** — собирает риск, формирует объяснение на русском и рекомендованное действие; пишет в БД + аудит-лог.
- **UI** — аналитическая консоль (см. §6).

## 3. Своя модель (критерий №2 — ядро проекта)

- **Тип:** обучаемый риск-классификатор = мультиязычные эмбеддинги (open-source `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`, заморожены) **+ наши инженерные признаки** → **наша обученная голова** (LogisticRegression или GradientBoosting, sklearn).
- **Наши признаки (примеры):** наличие триггеров «гарантированный доход / X% в месяц», названия казино/букмекеров, реф-ссылки, Telegram/WhatsApp-CTA «пиши в личку», промокоды, крипто-кошельки/реквизиты, urgency-лексика, эмодзи-деньги, и т.д.
- **Классы:** `гемблинг` · `финпирамида/HYIP` · `мошенничество/реф-схема` · `чисто`.
  - В класс `чисто` обязательно включаем **«трудные» негативы** (легальная реклама, финликбез, новости о казино) — чтобы модель не штамповала ложные срабатывания (важно для критерия №3).
- **Данные:** датасет ~400–600 размеченных текстов **RU + KZ**, построенных на реальных публичных паттернах мошеннической рекламы. train/test split (стратифицированный).
- **Доказуемость (для питча):** отчёт с **F1 по классам + confusion matrix + примеры** → «железный» аргумент за критерий №2.
- **Объяснимость:** атрибуция признаков (коэффициенты модели / вклад признаков) → человекочитаемые причины на русском: «обещание дохода 30%/мес», «упоминание бренда казино», «реф-ссылка + призыв в личку».

**Важно по критерию №2:** внешние open-source экстракторы (Whisper, EasyOCR, CLIP, эмбеддинги) — это **локальные фичеризаторы**, а не «сервисы». Оцениваемая собственная модель — это обученная нами голова-классификатор поверх фьюзнутых признаков. LLM (Claude/GPT) **не используется** в скоринге; допускается только опционально для генерации человекочитаемого текста объяснения, и это явно отделяется от решения о риске.

## 4. Мультимодальный разбор (полный мультимодал)

| Модальность | Инструмент | Примечание |
|---|---|---|
| Аудио → текст | `faster-whisper` (локально, CPU-friendly) | расшифровка речи |
| Текст с экрана / субтитры | `EasyOCR` (RU+KZ+EN) по ключевым кадрам | названия казино, промо, «гарант. доход» |
| Визуальные маркеры | `open-clip` zero-shot | концепты: казино/рулетка/ставки/демонстрация денег/авто/люкс |
| Caption/описание | напрямую из метаданных | основной текстовый сигнал |
| Скачивание медиа | `yt-dlp` | для live-ссылок |

Все признаки **фьюзятся** в единый вектор и идут в нашу модель.

### Робастность демо (критично!)
- В seed-датасете **все признаки предвычислены и закэшированы** → скоринг мгновенный, демо не зависит от тяжёлых моделей.
- Тяжёлый пайплайн (Whisper+OCR+CLIP) запускается **только** на «живой» загрузке видео — как опциональный wow-момент.
- **Лестница деградации:** если CLIP/Whisper не встанут на ноутбуке — визуал/аудио опциональны; ядро (текст+OCR) работает; демо на кэше работает всегда.

## 5. Дополнительные фичи (наслаиваются на ядро, с приоритетами)

Все фичи переиспользуют общий слой данных (особенно извлечённые **сущности**), поэтому 3 из 4 почти бесплатны.

| Приоритет | Фича | Что даёт | Стоимость |
|---|---|---|---|
| **P0** | Ядро: pipeline + модель + консоль + кэш-датасет + live-upload | базовое демо | — |
| **P1** | **Граф связей** | сеть аккаунтов/объектов: один бренд казино / Telegram-ссылка / промокод / крипто-кошелёк → выявление координированных сетей и реф-рингов. Бьёт в «скрытые взаимосвязи». | низкая (рёбра из уже извлечённых сущностей) |
| **P2** | **Экспорт дела (PDF)** | официальное досье по флагнутому посту/аккаунту: доказательства + риск + рекомендация. Усиливает «практическую применимость». | низкая |
| **P3** | **Аналитика/тренды** | сводный экран: динамика по категориям, топ брендов казино/пирамид, разрез по платформам. Показывает масштаб. | низкая (SQL-агрегации) |
| **P4** | **Telegram-платформа** | Telegram-посты в датасете (кэш-признаки) → честно покрывает «и другие платформы»; опц. live-fetch публичного канала. | средняя (live — опционально) |

**Safety-net:** на каждом срезе (P0, P0+P1, …) есть полноценное демо. Время кончилось — отрезаем сверху, ядро остаётся целым.

## 6. Аналитическая консоль (UI) и демо-сценарий

**Экраны:**
1. **Лента / очередь** — входящие посты «капают» в реальном времени (симуляция потока), авто-скорятся, сортируются по риску (красный→жёлтый→зелёный), бейдж категории и платформы.
2. **Drill-down карточки** — видео/превью, транскрипт с подсветкой триггеров, OCR-текст, визуал-концепты (CLIP), список сработавших паттернов, **объяснение «почему опасно»**, рекомендованное действие, кнопка «Экспорт дела (PDF)».
3. **Граф связей** — интерактивный граф (узлы: аккаунты/бренды/ссылки/кошельки; рёбра: совместное появление) с подсветкой кластеров высокого риска.
4. **Тренды** — дашборд агрегаций.
5. **Live-проверка** — «вставь ссылку / загрузи видео» → реальный мультимодальный разбор → вердикт.

**Демо-скрипт (3 минуты):**
1. (0:30) Проблема + лента: посты капают, авто-скорятся, очередь сортируется по риску.
2. (1:15) Клик по топ-риску → drill-down: доказательства по модальностям + объяснение + рекомендация. → кнопка PDF-досье.
3. (0:30) Граф связей: «эти 6 аккаунтов пушат один бренд казино через один Telegram» → координированная сеть.
4. (0:30) Live-загрузка свежего видео → реальный мультимодальный разбор → вердикт.
5. (0:15) Метрики модели + «как масштабируется / этика».

## 7. Этика и ИБ (критерий №3) + масштабируемость (критерий №4)

**Этика / ИБ:**
- Только **публичные** данные; минимизация PII (храним публичный хэндл и контент, не профилируем личность).
- **Human-in-the-loop:** система *приоритизирует для проверки*, **не блокирует и не обвиняет автоматически**. Финальное решение — за аналитиком/юристом.
- **Объяснимость** к каждому флагу (без «чёрного ящика»).
- Калибровка порогов, явный контроль ложных срабатываний (precision важнее recall для авто-эскалации).
- **Аудит-лог** всех решений системы.
- Привязка к мандату АФМ и законодательству РК; материалы, противоречащие закону РК и этике, не используются.

**Масштабируемость:**
- Stateless-воркеры экстракторов + очередь задач; батчинг инференса.
- Горизонтальное масштабирование экстракторов и сервинга модели.
- Путь **MVP (SQLite, in-process) → прод (Postgres + очередь + объектное хранилище медиа)**.
- Оценка пропускной способности и стоимости (видео/час, GPU vs CPU).

## 8. Стек и запуск

- **Backend/ML:** Python 3.11, **FastAPI** (отдаёт API + статический дашборд), **SQLite**.
- **Экстракторы:** `yt-dlp`, `faster-whisper`, `easyocr`, `open-clip-torch`.
- **Модель:** `sentence-transformers` (эмбеддинги) + `scikit-learn` (наша голова).
- **Граф:** построение на бэкенде; визуализация — `vis-network`/`cytoscape.js` (CDN) на фронте.
- **PDF:** генерация на бэкенде (напр. `weasyprint`/`reportlab`) или HTML→печать.
- **Frontend:** одностраничный дашборд, HTML + Tailwind (CDN) + лёгкий JS (Alpine.js/vanilla), polling API. «SOC-console» вид, без тяжёлой сборки. Выглядит как продукт (критерий №5).
- **Запуск:** одна команда (`run.bat` / `python -m app`); модели подтягиваются на этапе `setup`.

**Артефакты к защите:**
1. Работающее приложение (консоль).
2. Обученная модель + отчёт с метриками.
3. Короткий питч-дек (HTML/PDF).
4. 3-минутный скрипт защиты + Q&A-заготовки.

## 9. Жёсткие рамки YAGNI (что НЕ делаем)

Не делаем: реальный непрерывный краулер с авторизацией под нагрузкой; обучение визуальной модели с нуля; мобильное приложение; кластер БД; аккаунты/роли/мультиюзер; реальный live-скрейпинг Instagram/TikTok под нагрузкой на сцене. Поток «постоянного мониторинга» **симулируем** seed-лентой + честный live-путь (одиночная ссылка/файл).

## 10. Риски и митигаця

| Риск | Митигация |
|---|---|
| Тяжёлые модели не встают/тормозят на ноутбуке | кэш-признаки в датасете; тяжёлый путь только на live-upload; лестница деградации |
| Не хватает 24 ч на все фичи | приоритетная лестница P0→P4, отрезаем сверху |
| Wi-Fi на площадке/блокировки | демо работает офлайн на кэше; модели скачаны заранее |
| Жюри сомневается, что модель «своя» | показываем код обучения + метрики + отсутствие внешних API в скоринге |
| Ложные срабатывания → этический риск | human-in-the-loop, объяснимость, калибровка порога, «трудные» негативы в датасете |
